# 分布式智慧家居系统

> **不换电器，也能让家变聪明。**
> 一个开源方案 —— 不造智能电器，只造「让已有电器能联网的那一层」。

---

## 这个项目想解决什么

智能家居有一个**隐形的门槛**：想智能化，先得换家当。

| 谁 | 为什么被挡在门外 |
|---|---|
| **租房的人** | 不能改装修、不能打孔、不能换电器，搬走还要还原 |
| **老房子** | 没留零线、不能重新布线 |
| **老人** | 不会用 App，需要的是一块刻了字的物理按键 |
| **预算有限的人** | 不愿意为"智能"付一次全屋装修的钱 |

这四类人加起来，比买得起全屋智能的人多得多。

这个项目想绕过那道门槛：**家里的灯、空调、窗帘一件都不用换，加一层"接入"就能联网。**

## 六层结构

```
云端      MQTT Broker · 规则引擎 · 仪表盘 · 异地通道 · AI     ← 我们做
界面      手机 PWA · Web 仪表盘 · 壁挂终端（旧手机+物理键）    ← 我们做
节点层    ESP32-C3 三种形态：GPIO 型 / 红外型 / 总线型         ← 我们做
接入层    智能插座 · 红外发射管 · 按键并联 · RS485 · 换执行件   ← 我们做
电器层    灯 · 空调 · 新风 · 地暖 · 窗帘 · 门锁                ← 用户已有
物理兜底  墙面开关 · 三档选择器 · 应急拨杆                     ← 不经过芯片
```

**上面四层是我们造的；下面两层不是** —— 电器是用户家里的既有资产，物理兜底是机械结构。

### 节点的三种形态

| 形态 | 一台 C3 管几台 | 靠什么 |
|---|---|---|
| GPIO 型 | 1–4 台 | 继电器 / 智能插座 |
| 红外型 | 一个房间的红外设备 | 红外发射管 + 码库 |
| 总线型 | 一条 RS485 总线上的 N 台 | RS485 模块 + 点表 |

---

## 三条设计原则

**① 状态只认实测，不认命令**
节点是唯一真源。界面不做"点了就变"的乐观更新，等节点回报才确认。

**② 物理兜底永远存在**
日常按钮只报位置给 MCU，MCU 是唯一执行者；另加三档选择器（自动 / 强开 / 强关），MCU 挂了也能开灯、能彻底断电。

**③ 本地永远优于云端**
终端和云都挂了，家里还能靠手开灯。云端是增强，不是依赖。

## 与同类项目的关系

这个方向**不是空白**，已有成熟实现：

| 项目 | 是什么 | 我们的差别 |
|---|---|---|
| [OpenMQTTGateway](https://docs.openmqttgateway.com) | 开源固件，把 BLE / RF / 红外 / LoRa 译成 MQTT（4.1k★） | 它只管翻译；我们管接入 + 状态 + 物理兜底 |
| [Home Assistant](https://www.home-assistant.io) | 开源自动化平台 | 它是软件层，不提供硬件接入方案 |
| SwitchBot | 商业，非侵入式改造（贴装机器人 / 窗帘机） | 它闭源、绑自家 App 与云 |

**我们能站住的三处空白：**

1. **物理兜底** —— 上面这些都不管"MCU 死了怎么办"
2. **状态诚实** —— 设备被切到手动后，界面明说"不可远程"，而不是让用户点十次没反应
3. **中文的完整文档** —— 含翻车案例、模拟保真度边界、决策台账

> 接入协议的**广度上不如 OMG**（它支持 100+ BLE 设备解码）。我们的取舍是：用开源现成的（`IRremoteESP8266` 等），把精力放在**体系与可靠性**上。

## 项目性质（重要）

本项目是**最大程度模拟**，目的是验证架构与想法，不是可上市的产品。

- 全部 **12V 直流**，**不接 220V**
- 产品化（安规、EMC、可靠性、3C 认证、量产）是商家的事
- **能证明**：拓扑逻辑、通信协议、状态同步、场景编排、故障模式
- **不能证明**：电气安全、负载特性、发热与线径、EMC、安规认证
