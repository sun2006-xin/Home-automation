## 1. 十四份文档，各自的核心结论

### 00 · 立项书
- 范围收口：**只做分布式智慧家居一个项目**，51 学习项目已移除
- 51 现仅作终端按键条（管 4 个固定键），不承担网络与决策
- 里程碑 M0–M7，最大风险是"备考挤压导致中断"，对策是里程碑粒度做小

### 01 · 架构设计（参考，部分被 10 取代）
- 四层分层：`app / protocol / driver / bsp`，下层不知道上层存在
- `transport_t` 与 `cloud_port` 两个抽象口子 —— 换传输、换云平台不改业务代码
- 节点四态状态机：BOOT → CONNECT → ONLINE / RETRY / OFFLINE

### 02 · 硬件与引脚（参考）
- 51 面板引脚分配与 **5 类冲突**（P2 口、串口、P3.5/P3.7 三方复用等）
- 结论：LCD 改 I2C、按键只用 K3/K4、去掉 DS1302、MQ-2 走 DO

### 03 · 原方案技术审查（参考）
- 原始 docx 的 8 个问题，其中 2 个是"按文档做必然失败"级别
- 最严重：HC-05 与 ESP8266 抢唯一 UART；LED 与 LCD 抢 P2 口
- 值得保留：四阶段划分、驱动层切分、传感器初始化时序

### 04 · 开发日志（**必看**）
- 追加式记录，含每次决策**和推翻过程**（含我给出的错误方案被纠正的经过）
- 每次开工第一件事：看最后一条

### 05 · 术语表
- 30 余词：broker / topic / retain / LWT / bridge / 盲网关 / 能力模型等
- 每个词一句人话 + 一句本项目落地方式

### 06 · 完整开发计划
- 26 个模块清单（含接口签名与工时），五层划分
- MQTT 主题表定稿、OTA 流程、安全设计
- M8 里程碑 WBS + 15 条测试用例（**其中 9 条是反向用例**）
- 第 17 章《交付与可靠性清单》：交付五件套、中枢可替换、误报抑制、永不远程锁死

### 08 · 市场方案与落地研究（**核心**）
- 六条路线：米家 / 华为 PLC-IoT / Aqara / 涂鸦 / KNX / Matter
- **六起真实翻车案例**：龙湖×海尔网关屏坏半年、万科×良信不可替换、商家远程锁网关
- 智慧养老赛道：毫米波雷达 + 三级闭环（眼-脑-手），设备只占 1/3
- 附录：智能开关四种做法对比，含**机械定时开关 ON-AUTO-OFF 几十年先例**

### 09 · 实现细节解剖（**核心**）
- MIoT-Spec 的 URN 命名体系、属性八字段、miIO 报文 32 字节头与加解密
- Matter 的端点/簇模型、**刻度陷阱**（CurrentLevel 0–254，温度 int16 = 0.01℃）
- Home Assistant MQTT Discovery 报文 —— 可直接抄来实现零代码接入
- **能力规范 v1 冻结**：4 种能力、属性四件套、`_discovery` 报文、5 个指令动词

### 10 · 系统结构定稿（**核心**）
- 四个部分：用户/手机、云端、本地终端、电器节点 + 物理兜底
- **六条链路** + **故障矩阵**（6 种故障 × 5 项能力）
- 三条实现约束：双连接四坑、物理开关只报位置、AI 上云要算带宽与隐私
- 唯一死角：终端 + 云同时挂 → 只剩物理开关（无法用软件消除，需硬件兜底）

### 11 · 产品与功能设计（**核心**）
- **10 台家电清单**（3 梯队），4 种能力类型，5 个房间分布
- 终端 = 旧手机壁挂 + 51 按键条；触摸屏负责"看"，物理键负责"按"
- **开关接法：开关只报位置给 MCU，MCU 唯一执行；三档选择器管模式；光耦管事实**
- 12V 全模拟方案 + **模拟保真度矩阵**（能证明架构，不能证明安规）
- 门锁模拟五条纪律：fail-safe、机械应急、本地鉴权、不做纯云开锁、本地留痕

### 12 · 界面设计规范
- 抄米家"一眼看完"、HA"卡片模型"、KNX"能盲操"；避所有人的"层级深"
- 三条硬规则：高频操作 ≤2 次点击 / 状态不做乐观更新 / 卡片必须显示"谁在何时操作"
- 同类设备一卡多实例，`‹ 1/3 ›` 切换；**UI 只显示名称，编号只在调试页**

### 13 · 场景与联动设计
- 场景 ≠ 自动化：前者人点、一次性、有进度可取消；后者条件触发、持续监听
- **执行实例**：run_id / state / progress / done / failed，必须能取消
- 离家"全关"不能用广播（会误伤冰箱路由器），要中枢逐个下发跳过 critical
- 场景与自动化**底层同构**，只差 `trigger`（manual / device / schedule）

## 2. 已定决策台账（22 条）

### A · 结构与范围

| # | 决策 | 依据 |
|---|---|---|
| D01 | 最小单元 = **一个电器 + 一块 ESP32-C3** | 分布式，无单点 |
| D02 | 51 **不做主控**，仅作终端按键条 | 1 个 UART、256B RAM 撑不起节点 |
| D03 | 云端 = broker + 规则引擎 + 仪表盘 + 异地通道 + AI | 只做出口，不做实时判断 |
| D04 | 终端 = 旧手机壁挂 + 51 按键条 | 成本 0，且"看"与"按"分开 |
| D05 | AI 作为独立模块（M9），不进主线 | 与 YOLOv5 学习线隔离，避免污染 |

### B · 硬件与接线

| # | 决策 | 依据 |
|---|---|---|
| D06 | **全部 12V 直流模拟，不碰 220V** | 安全；拓扑逻辑与强电一致 |
| D07 | 物理开关**只报位置给 MCU**，MCU 唯一执行 | 否则并联成"或"逻辑，手机关不掉灯 |
| D08 | **三档选择器**：自动 / 强开 / 强关；档位回读给 MCU | 继承定时开关几十年验证的结构 |
| D09 | 加**光耦电流检测**（约 1 元） | 开关位置是意图，电流才是事实 |
| D10 | 灯只做开关，不做调光 | 省掉 PWM + 驱动一整档复杂度 |
| D11 | 窗帘做 0–100% 定位 | 能力强于三态，需限位或计时校准 |

### C · 通信与协议

| # | 决策 | 依据 |
|---|---|---|
| D12 | 节点**双连**（本地 broker + 云 broker） | 终端挂了仍可远程；分期实现（M2–M4 单连，M7 双连） |
| D13 | **传输层不自研**（WiFi + TCP + MQTT） | 重造收益为零、bug 无限 |
| D14 | **应用层自研**：主题 + 载荷 + 指令语义 + 能力声明 | 这才是项目价值所在 |
| D15 | 4 种能力：`switch` / `cover` / `dimmer` / `sensor` | 覆盖全部 10 台设备 |
| D16 | 刻度约定：温度 int16 = 0.1℃；百分比 0–100；布尔用 0/1 | 照 Matter 的失败教训定死 |

### D · 界面与交互

| # | 决策 | 依据 |
|---|---|---|
| D17 | **状态只认实测**，界面不做乐观更新 | 否则出现"两套系统" |
| D18 | 手机端用 **PWA**，不做原生 App | 一套代码多端，加到主屏像 App |
| D19 | 云端界面**自写**，抄长避短 | 见 docs/12 对照表 |
| D20 | 同类设备一卡多实例 + 编号切换 | 避免首屏爆炸；UI 只显示名称 |

### E · 工程与质量

| # | 决策 | 依据 |
|---|---|---|
| D21 | 门锁做，但走**模拟版五条纪律** | 开锁失败的后果不是体验差，是进不了家 |
| D22 | 交付五件套 + 中枢可替换 + 误报抑制 + **永不远程锁死** | 六起翻车案例的直接教训 |

## 3. 明确不做（防止范围膨胀）

| 不做 | 理由 |
|---|---|
| 51 做节点主控 | 资源不够，且已降级为按键条 |
| 220V 强电实操 | 安全；模拟已能验证架构 |
| Matter 认证 | $5k–15k、6–12 周 |
| BLE Mesh / Zigbee | 复杂度高，本项目场景用不着 |
| 自研加密协议 | miIO 的 token 泄露事故是前鉴 |
| 摄像头 / 人脸识别（v1） | 归 M9 独立模块 |
| 电商 / 社交 / 主题皮肤 | 见 docs/12 克制清单 |

## 5. 定版后的变更规则

| 版本号 | 允许改什么 | 例子 |
|---|---|---|
| **v1.x** | 措辞、补充说明、纠错、补图 | 把开关接法讲得更清楚 |
| **v2.0** | 改范围 / 结构 / 关键决策 | 增加电器、改协议字段、改终端形态 |

**规则：**
1. 改决策必须**在 docs/04 开发日志追加一条**，写清"旧结论 / 新结论 / 为什么改"
2. 每份文档顶部不需要写版本号，**版本以本文为准**
3. 本文定版后**不再修改**；新版另建 `V2.0-定版说明.md`

## 6. 定版之后做什么

**下一步只有一个：M1 —— 让一块 C3 通过蓝牙把窗帘动起来。**

| M1 六步 | 产出 |
|---|---|
| 1. 环境与点灯 | 能编译烧录 |
| 2. `node_config.h` + `link.h` 定接口 | 接口冻结 |
| 3. 步进四相八拍驱动 | 2048 步精确回原位 |
| 4. `link_gpio` 实现 cover 能力 | 能走到 50% |
