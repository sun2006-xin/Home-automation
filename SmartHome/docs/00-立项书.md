# 00 · 立项书

## 0. 项目边界（重要）

本项目（**项目二**）**不依赖 51 单片机**。51 已被划归姊妹项目 [51-SmartHome](../../51-SmartHome/README.md)（项目一：学习项目）。

| | 项目一 51-SmartHome | 项目二 SmartHome（本文件） |
|---|---|---|
| 目的 | 学习：打熟 51 与外设 | 产品：能装进房子的分布式系统 |
| 是否依赖对方 | 否 | 否（51 面板仅可选扩展，已从主线移除） |
| 推进方式 | 碎片时间，书桌上就能干 | 需网购元件 + 整块时间 |

分拆理由：
1. 51 的价值在"基本功"，不在"现代化系统"。硬让它承担 broker / 网关，两头都做不好。
2. 两个项目抢同一份时间，备考期更容易双双烂尾。分开后可错峰推进。
3. 共用知识（步进电机时序、LCD、传感器、行协议）可复制，但仓库独立、进度独立。

## 1. 项目背景与认知修正

原始需求文档《51智慧家居.docx》规划了"单块 51 + 堆外设"的四阶段系统。该方案作为**技能训练阶梯**是优秀的（GPIO / UART / 单总线 / ADC / 电机 / 云平台全覆盖），但作为**产品形态不成立**：

> 所有电器用线缆汇集到一块 51 上 —— 不现实，也不是分布式。真装进一套房子里，走线量、故障面、扩展成本都不可接受。

**由此确立真正的架构：**

- **最小单元 = 一个电器 + 一块 ESP32-C3**（C3 是每个电器的网卡与边缘大脑）
- **51 退居中控面板**（可选，负责显示与本地联动），且**不在数据路径上**
- 节点之间通过 MQTT 总线平级互联，手机 / 云 / 51 都是同级客户端

详见 `docs/01-架构设计.md`。

## 2. 目标与非目标

### 2.1 目标

| 优先级 | 目标 | 判定方式 |
|---|---|---|
| P0 | 单节点自治：一块 C3 控制一个真实电器 | 手机蓝牙直连能开合窗帘 |
| P0 | 节点接入总线：多节点通过 MQTT 并存 | 2 个节点同时在线，互不干扰 |
| P1 | 近场直控：BLE / WiFi AP 无需路由器可用 | 拔掉路由器，手机仍能控制 |
| P1 | 远场控制：异地手机 4G 可操作 | 手机切 4G 能开关灯，延迟 < 2s |
| P2 | 上位机可视化 / 中枢规则编排 | 实时曲线 + 设备开关 + 报警记录 |
| P3 | 工程化：OTA / 心跳 / 断线重连 | 断电重启 60s 内自恢复；OTA 成功 |
| — | （可选）51 物理面板 | 见项目一 51-SmartHome，不属本项目主线 |

### 2.2 非目标（明确不做）

- ❌ 不做"所有电器有线连到一块 51"的形态（已判定不成立）
- ❌ 不让 51 承担网关 / 路由职责（见 docs/01 第 4.2 节四条理由）
- ❌ 不做 Matter / Thread 认证级实现（认证 $5k–15k，属远期）
- ❌ 不做摄像头 / 人脸识别（与 YOLOv5 学习线隔离）
- ❌ 不做 PCB 打板，全部现成模块
- ❌ 不买 HC-05、DS1302、XPT2046（理由见 docs/03）

## 3. 里程碑（版本化）

| ID | 里程碑 | 交付物 | 验收标准 | 状态 |
|---|---|---|---|---|
| M0 | 立项与架构 | 文档集 + 目录骨架 | 架构定稿，引脚与采购清单定稿 | ✅ |
| **M1** | **单节点原型（形态 A）** | C3 节点固件 v0.1 + 一个真实电器 | 手机 BLE 直连，能让窗帘电机正反转/定位；无路由器也能用 | ⬜ |
| M2 | 节点上总线 | 节点固件 v0.2 + 本地 Mosquitto | 手机同网 MQTT 控制；状态 retain；掉线 LWT 生效 | ⬜ |
| M3 | **形态 B 达成**：第二节点 | 第二块 C3 + 第二个电器 | 两节点独立在线；拔掉任一电源，另一个照常；复制固件改 ID 即可 | ⬜ |
| M4 | **形态 C 达成**：远场 | 云 broker + 内网穿透 | 手机 4G 异地控制，延迟 < 2s；断网不影响本地 | ⬜ |
| M5 | **形态 C 收口**：中枢规则编排 | 中枢上的跨设备场景 | 烟雾报警 → 自动开窗；温度超限 → 自动开风扇；断网仍生效 | ⬜ |
| — | ⏸ 可选：51 物理面板 | 见项目一 [51-SmartHome](../../51-SmartHome/README.md) | 想要一块墙上看得见的面板时才做，不阻塞主线 | ⏸ |
| M6 | 上位机 | PyQt5 或 HA 面板 | 实时曲线 + 开关 + 报警记录 | ⬜ |
| M7 | 工程化 | OTA + 心跳 + 重连状态机 | 断电重启自恢复；OTA 升级成功 | ⬜ |

> **顺序说明**：M1 必须先做"纯 C3 节点"，因为它是所有形态的共同地基。51 面板看似更完整，但它的实现完全依赖节点固件先跑通。

## 4. 并行线：51 技能预科（不占主线工期）

原方案的 51 四阶段不废弃，转为**备考间隙的技能训练**，目的是把 GPIO / UART / 单总线 / 电机 / 状态机这些基本功练熟，为 M5 的面板打底。

| 预科 | 内容 | 与主线关系 |
|---|---|---|
| 预一 | LED + 按键 + I2C LCD1602（软件 I2C） | 直接用于 M5 面板 |
| 预二 | DS18B20 + 蜂鸣器 | 直接用于 M5 面板 |
| 预三 | 28BYJ-48 步进电机 + ULN2003 | 与 M1 窗帘节点同款电机，代码可对照 |
| 预四 | UART 行协议收发 | 就是 M5 的 51 侧协议层 |

> 预科不设硬期限。它的作用是"手不生"，而不是"必须完成"。

## 5. 待决策事项

### 5.1 节点芯片（阻塞 M1）

| 方案 | 硬件 | 单价 | 结论 |
|---|---|---|---|
| **ESP32-C3 SuperMini** | 1 块/节点 | ~12 元 | ✅ **采用**：WiFi + BLE 5 双模、4MB Flash 够 OTA、RAM 充足、GPIO 多 |
| ESP-01S | 1 块/节点 | ~8 元 | ❌ 无 BLE，无法"手机蓝牙直连"；RAM 小，OTA 吃力 |
| ESP32-S3 | 1 块/节点 | ~25 元 | 过剩，除非将来加摄像头 |

**C3 是唯一能同时满足"蓝牙近场直控 + WiFi 远场 + OTA"三项需求的最低成本方案。**

### 5.2 Broker 位置（阻塞 M2）

| 方案 | 成本 | 说明 |
|---|---|---|
| 一台常开 C3 跑 Mosquitto（ESP32 版） | 0（复用） | 轻量，够 20 节点 |
| 路由器刷 OpenWrt + Mosquitto | 0 | 最优雅，但要看路由器型号 |
| 旧手机 / 树莓派 | 0–200 元 | 最省心，可同时跑 Home Assistant |
| 公共云 broker（巴法云 / EMQX Cloud） | 免费额度受限 | 只做 M4 远场用，不做主力 |

**建议**：M2 先用"旧手机/树莓派跑 Mosquitto"，M4 再加穿透。

## 6. 时间预算

与转本备考并行，**每周 ≤ 5 小时**（3 次 × 1.5h）。因此：

- 每个里程碑必须 **2–3 周内出可演示结果**
- 单任务预估超 6 小时必须拆分
- 备考周暂停代码，只更新文档
