# 交接文档 · 从零上手

> 写给接手这个项目的人。
> 照着做完第 3 节，你就能独立开发第一个节点，不需要读完那 15 份文档。

---

## 0. 30 秒了解

**这是什么**：一套开源的智能家居方案 —— 不造智能电器，只造「让已有电器能联网的那一层」。

**现在在哪一步**：规划完成，**代码一行没写**。你的第一个任务是让一块 ESP32-C3 通过蓝牙把窗帘动起来。

**技术栈**：ESP32-C3 + Arduino 框架 + PlatformIO；后期加 MQTT；全部 12V 直流模拟。

---

## 1. 开工前必须知道的三件事

| # | 事情 | 为什么重要 |
|---|---|---|
| 1 | **不接 220V，全 12V 模拟** | 安全第一。拓扑逻辑与强电一致，但电压安全 |
| 2 | **代码目录已规划好，但都是空的** | 不要自己另起炉灶，按第 4 节的结构放文件 |
| 3 | **目标用户是不会折腾的人** | 这决定了所有设计取舍：能开箱即用、断网可用、老人能用 |

> 仓库目前是**私有**的。要加入协作，需要仓库所有者在 GitHub 上邀请你。

## 2. 环境准备（约 30 分钟）

### 2.1 装工具

1. 装 **VS Code**
2. 在 VS Code 扩展里搜 **PlatformIO IDE**，安装（会顺带装 Python 和工具链，比较慢）
3. 装 **CP210x / CH340 串口驱动**（C3 板子一般是 CH340 或原生 USB，看板子）

### 2.2 建工程

在 `SmartHome/firmware/nodeESP/` 下建工程，选板子 **Espressif ESP32-C3-DevKitM-1**，框架选 **Arduino**。

`platformio.ini` 内容（可直接用）：

```ini
[env:esp32-c3]
platform = espressif32
board = esp32-c3-devkitm-1
framework = arduino
monitor_speed = 115200
upload_speed = 921600
build_flags =
    -DCORE_DEBUG_LEVEL=3
```

M1 阶段**不需要**任何第三方库。等做 M2（接 MQTT）时再加：

```ini
lib_deps =
    knolleary/PubSubClient
    bblanchon/ArduinoJson
```

### 2.3 验证：点亮板载 LED

写一个 Blink（`delay(500)` 那种就行），编译 → 烧录。

**烧录注意**：如果提示连接超时，**按住板子上的 BOOT 键，再插 USB**，进入下载模式。

看到 LED 闪 = 环境通了。**这一步没通之前不要往下走。**

## 3. 第一个任务：M1（打勾清单）

**目标**：手机通过蓝牙发一个 `pos=50`，窗帘电机走到一半，状态回传给手机。

| # | 任务 | 验收标准 | 预估 |
|---|---|---|---|
| 1 | 环境 + Blink | 板载 LED 能闪 | 30 min |
| 2 | 建目录骨架 + `node_config.h` | `DEVICE_ID="C01"`、`LINK_IMPL=link_gpio` | 30 min |
| 3 | `drv_stepper`：四相八拍 | 正转 2048 步精确回到原位，不丢步 | 4–5 h |
| 4 | `link_gpio` 实现 `cover` 能力 | 调 `Link_Apply("set","50")` 能走到 50% | 2 h |
| 5 | `net_ble`：自定义 GATT 服务 | 手机 nRF Connect 能读写特征 | 3 h |
| 6 | 手机发 `pos=50` → 窗帘动 | 端到端打通，状态回报 `pos:50` | 1 h |

**M1 完成标志**：录一段 15 秒视频，手机点一下，窗帘走到一半。

> **M1 不需要**：MQTT、WiFi、云端、手机 App、其他任何设备。只有 BLE。

## 4. 代码目录与文件职责

```
firmware/nodeESP/
├── platformio.ini
├── src/
│   ├── main.cpp              启动、初始化、主循环
│   ├── node_config.h         ★ 唯一差异点：DEVICE_ID / LINK_IMPL / 引脚宏
│   ├── link/                 ★ 接入层（四种接法的共同接口）
│   │   ├── link.h               接口定义，上层只依赖它
│   │   ├── link_gpio.cpp        继电器 / 步进（M1 用这个）
│   │   ├── link_ir.cpp          红外（M8 才做，先留空）
│   │   ├── link_modbus.cpp      RS485（M8 才做，先留空）
│   │   └── link_private.cpp     厂家私有协议（按需）
│   ├── driver/               硬件驱动，不含业务判断
│   │   ├── drv_stepper.cpp   ├── drv_relay.cpp
│   │   ├── drv_led.cpp       └── drv_key.cpp
│   ├── app/                  业务逻辑
│   │   ├── app_cap.cpp          能力模型：哪些能力、怎么执行
│   │   ├── app_state.cpp        状态表 + 序列化
│   │   └── app_rule.cpp         节点本地规则（只有同节点内的）
│   ├── net/                  通信
│   │   ├── net_ble.cpp          M1 用
│   │   └── net_mqtt.cpp         M2 用
│   └── sys/                  系统
│       ├── sys_nvs.cpp          存 WiFi 账号 / device_id
│       └── sys_ota.cpp          OTA（M7 才做）
```

### 依赖方向（严格单向，不许反向）

```
app → link → driver
 ↓      ↓
net    sys
```

**两个审查铁律：**
- `driver/` 里出现 MQTT 相关调用 = 缺陷
- `app/` 里出现 `digitalWrite` = 缺陷

## 5. 必须遵守的约定

### 5.1 设备编号

```
<类型码><两位序号>    例：L01 / C01 / F01 / H01 / S01 / D01

L 灯   C 窗帘   F 风扇/继电器   H 加热类（热水器）   S 传感器   D 门锁
```

**界面上只显示名称，编号只在调试页出现。**

### 5.2 MQTT 主题（M2 起用）

```
sh/{home_id}/{device_id}/cmd      下行指令
sh/{home_id}/{device_id}/state    上行状态（retain = true）
sh/{home_id}/{device_id}/online   在线状态（LWT 遗嘱）
sh/{home_id}/_discovery           能力声明（retain）
```

### 5.3 指令动词只有 5 个

`set` / `toggle` / `open` / `close` / `stop`

不许自创新动词。要加新动作，先改文档再改代码。

### 5.4 状态上报

- **变化即报**（去抖 200ms）
- **每 30 秒心跳一次**
- 状态必须带 `src` 字段：`wall`（墙面开关）/ `app`（App）/ `rule`（规则）

### 5.5 每个文件顶部三行注释

```c
/* 职责：步进电机四相八拍驱动，只负责走步，不做位置判断
   引脚：P1.0-P1.3 经 ULN2003，顺序 IN1-IN4
   已知坑：启动瞬间拉低电源会导致 MCU 复位，需独立供电 + 1000uF */
```

### 5.6 提交信息

```
feat(node): 实现步进电机四相八拍驱动
fix(ble): 修正 GATT 特征权限
docs: 补充接线说明
refactor(link): 抽出 link 接口
```

## 6. 五条红线

| # | 不许做 | 原因 |
|---|---|---|
| 1 | **接触 220V 强电** | 安全。全部 12V 模拟 |
| 2 | `driver/` 里写业务判断（`if temp > 30`） | 分层会烂掉，换板子要改两层 |
| 3 | 自己发明加密协议 | miIO 的 token 泄露事故是前鉴。用 TLS + broker ACL |
| 4 | 做"纯云端开锁" | 门锁必须本地鉴权，云只能发请求 |
| 5 | 修改 `docs/04-开发日志.md` 的历史 | 日志是追加式，改了就没法追溯决策 |

---

## 7. 十个常见坑

| # | 坑 | 解法 |
|---|---|---|
| 1 | 烧录连接超时 | 按住 BOOT 再插 USB |
| 2 | 串口监视器打不开 | 被上次的监视器占用，先关掉终端 |
| 3 | PlatformIO 首次编译卡很久 | 在下载工具链，10–20 分钟正常 |
| 4 | C3 的 **GPIO8 / GPIO9 是 strapping 引脚** | 影响启动模式，尽量不占 |
| 5 | 继电器推不动 | 要选**明确标注 3.3V 兼容**的模块，5V 光耦模块需要 4V 以上 |
| 6 | 步进电机一转，MCU 就复位 | 电机独立供电 + 并 1000µF + 共地单点。**12V 一样会复现** |
| 7 | MQTT 反复掉线 | 同一 broker 上 `client_id` 重复会互相踢 |
| 8 | 设备掉线了，界面还显示在线 | LWT 必须在 CONNECT 时就设置，不能事后补 |
| 9 | 状态"幽灵"（显示开着其实关了） | `retain` 用错。状态主题开 retain，命令主题不开 |
| 10 | 红外发不出去 | 需要 38kHz 载波调制，普通 GPIO 直接拉高拉低无效 |
