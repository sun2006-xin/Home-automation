## 一、长版 · 讲转变（约 450 字）

适合：朋友圈长文、公众号开头、项目介绍正文

---

一开始我想做的是十台智能电器：智能灯、智能窗帘、智能门锁，全都自己造一遍。

画了三天结构图，突然卡住了——门锁单拎出来就是一个完整产品，空调是另一个，窗帘又是一个。用户凭什么为了用我的系统，把家里的东西全换掉？

那个瞬间我意识到方向错了。

于是改了一件事：**不造电器，造"让电器能联网的那一层"。**

现在的结构是六层。上面四层是我们做的——云端、界面、控制器、接入方式；下面两层不是：**电器是用户家里本来就有的，物理开关是机械结构。**

一台 ESP32-C3 做成小控制器，三种形态：管一两台的通断型、管一个房间红外设备的遥控型、挂一条 RS485 总线管多台的总线型。

中间那层"接入"是关键——智能插座、红外发射管、按键并联、RS485 模块、换执行件，五种中介物对应五类电器。

结果是这样的：家里的灯不用换，空调不用换，窗帘轨道不用拆。

我一直觉得智能家居有个隐性门槛：想智能化，先得换家当。这套东西想绕开它。

不一定成。项目现在还在画图和买零件的阶段，一行代码没写。

但方向我觉得是对的：**别做又一个智能家居品牌，做一个让旧东西变聪明的方案。**

## 二、中版 · 讲痛点（约 180 字）

适合：朋友圈、短动态

---

做了几天智能家居，想通一件事。

一开始想做十台智能电器，全自己造。后来发现——门锁是独立产品，空调是另一个，窗帘又是一个。用户凭什么为了用我的系统，把家里全换掉？

所以改了：**不造电器，造"让电器能联网的那一层"。**

家里的灯、空调、窗帘都不换，加个中间层就能联网、能被手机控制、断网了还能用手开。

从"十台智能电器"改成"一台控制器 + 五种接法"。

方向变了，工作量少了十倍，用户也不用换家当。

## 四、技术版 · 讲架构（约 300 字）

适合：知乎、掘金、V2EX、技术群

---

做智能家居，最容易踩的坑是"自己造设备"。

这几天我把方向从「做十台智能电器」改成了「做一层接入」，理由很实在：门锁、空调、窗帘，每一个单拎出来都是独立产品，全都自己做不现实；而且用户已有的电器怎么办？

新方案是六层：**云端 / 界面 / 节点 / 接入中介 / 用户电器 / 物理兜底**。

- **节点**：ESP32-C3，三种形态（GPIO 通断 / 红外 / RS485 总线）
- **接入**：智能插座、红外发射管、按键并联、RS485 模块、换执行件
- **协议**：传输层用现成的（WiFi + TCP + MQTT），自研只在应用层（主题结构 + 载荷字段 + 能力声明）
- **关键设计**：物理开关只报位置给 MCU，MCU 是唯一执行者；另加三档选择器（自动/强开/强关）兜住 MCU 故障

不用换电器，也不用改电路板。10 台设备里：3 台是新增传感器，4 台插插座或换件，**真正动线路的只有 3 盏灯和 1 把锁**。

## 五、红线（哪些话不能说）

| ❌ 别说 | 原因 |
|---|---|
| "首创""第一""市面上没有" | KNX 执行器有手动模式、机械定时开关有 AUTO/OFF/ON 三档、米家万能遥控早就在做红外接入。一说就被反驳 |
| "独创三档开关" | 上方同因 |
| "做了一套智能家居系统" | 容易被理解成可售产品，实际是 12V 模拟验证 |
| "实现了智能开关" | 没做安规认证，不能称产品 |
| 夸大规模 / 假装有代码 | 现在真的一行没写，说实话反而可信 |

**能说的**：

| ✅ 可以说 | 因为 |
|---|---|
| "把工业级的自动/手动/应急三段控制，用 10 元成本做到家用墙面" | 准确、可辩护 |
| "消费级智能开关普遍不处理 MCU 故障层，我们补上了" | 事实 |
| "让用户不用换电器" | 这是真差异 |
| "还在买零件阶段" | 诚实，反而建立信任 |
