# 12 · 界面设计规范（自写版）

> 决策：**云端界面自写**，但设计上吸收各家优缺点。
> 本文覆盖三端：手机（PWA）、桌面（Web 仪表盘）、终端（旧手机壁挂）+ 51 按键条。

---

## 0. 抄什么，避什么

| 来源 | 值得抄 | 要避开的 |
|---|---|---|
| **米家** | 设备自动归类（灯光/窗帘/环境）、一屏概览、一键全关 | 电商入口；多品牌体验不一致；层级太深（开个灯点 3–4 下） |
| **华为鸿蒙智家** | 子系统分组（照明/遮阳/安防…）、场景化表达（回家/观影/睡眠） | 锁死生态；部分能力只在中控屏可用 |
| **Aqara** | 场景一键、自动化编辑直观、明确标注"本地执行/云端执行" | 高级功能藏在二级页面深处 |
| **涂鸦** | **场景（scene）与自动化（automation）明确分开** | 纯云依赖；界面同质化、无个性 |
| **Home Assistant** | 设备卡片模型、历史曲线、三段时间线（触发/条件/动作） | 配置门槛（YAML）、界面风格不统一 |
| **KNX 面板** | **实体按键 + 刻字、盲操优先** | 几乎没有信息展示 |

**一句话设计观**：抄米家的"能一眼看完"，抄 HA 的"卡片模型"，抄 KNX 的"能盲操"，避开所有人的"层级深"和"要联网才能用"。

---

## 1. 三条硬规则

| # | 规则 | 违反的后果 |
|---|---|---|
| 1 | **最高频操作必须首屏、点击 ≤2 次** | 用户宁可按墙上的开关，也不用你的 App |
| 2 | **状态永远来自节点，界面不做"乐观更新"** | 界面显示开了、实际是关的 → 变成"两套系统" |
| 3 | **每张设备卡片必须能回答"谁在何时操作的"** | 用户困惑"我没开啊"，然后不再信任系统 |

第 3 条的具体做法：卡片底部一行小字 `墙面开关 · 19:42` / `手机 · 20:11` / `规则:温度超标 · 18:30`。
成本极低（数据来自 `state.src` + `ts`），但对信任感的贡献极大。

## 2. 手机端（PWA）

### 2.1 首页信息层级（从下往上压）

```
① 状态条          时间 · 在线数（"全部在线 4/4"）
② 告警横幅        ★ 只在有告警时出现，红色，带"确认"按钮
③ 场景键 ×4       回家 / 离家 / 睡眠 / 全关
④ 设备卡片 2列    名称 · 状态 · 来源 · 快捷控制
⑤ 底部导航        首页 / 房间 / 场景 / 告警 / 设置（5 个，不多不少）
```

**为什么告警在场景键上面**：告警是"必须现在处理"的，场景是"想要才按"的。优先级天然不同。

### 2.2 设备卡片规范

```
┌─────────────────────┐
│ 客厅灯           ●  │  ← 名称 11px 次要色 + 在线点
│                     │
│ 已开                │  ← 主状态 15px 中等
│ 墙面开关 · 19:42     │  ← 来源 + 时间 11px 提示色
└─────────────────────┘
```

| 能力 | 主状态显示 | 快捷控制 |
|---|---|---|
| switch | 已开 / 已关 | 点击卡片直接切换（**不点进去**） |
| cover | `50%` + 进度条 | 点击展开滑条；长按 → 全开/全关 |
| sensor | `23.5 ℃` + 副值 | 点击进曲线；不可控 |
| dimmer | `30%` | 点击展开滑条 |

**关键取舍**：开关类设备**点击卡片即切换**，不要求"点进详情页再开"。
这是抄米家"一屏看完"，避免"点三下才能开灯"。

### 2.3 同一类设备不止一个：编号切换

问题：家里 3 个灯、2 个窗帘，卡片怎么放？

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 一设备一卡 | N 台 → N 张卡 | 直观，一眼看全 | 首屏爆炸，5 个灯就占满 |
| **B 一卡多实例** | 一张"灯光"卡，`‹ 1/3 ›` 切换 | 首屏干净 | 切换后看不到全部 |
| C 汇总卡 + 列表页 | 卡显示"灯 · 2/3 开"，点进看列表 | 兼顾 | 多一次点击 |

**采纳 B + C 混合：**

- 首页每张卡代表「**一个房间 × 一种能力**」
- 卡片右上 `‹ 1/3 ›` 可**直接切换实例**
- 卡片标题右侧显示汇总（如 `2/3 开`），提示"还有别的灯开着"
- 点卡片空白处 → 展开该能力的**列表页**（完整管理、重命名、排序）
- 长按卡片 → **换绑**它代表的设备

**四条必须处理的细节：**

| # | 细节 | 为什么 |
|---|---|---|
| 1 | 切换后**短暂高亮显示完整名称**（"客厅主灯 → 餐厅吊灯"） | 否则用户不知道切到哪了 |
| 2 | 用**左右箭头**，不用滑动手势 | 滑动与页面纵向滚动冲突，误触率高 |
| 3 | 离线实例在序号上加标记：`2/3·离线` | 避免切到一个"看不见的死设备" |
| 4 | 排序默认按 device_id，允许自定义 | 符合直觉，又能调整 |

**命名原则：UI 上只显示名称，编号只在调试页出现。**
`L01` 是内部标识，用户看到的是"客厅主灯"。编号永远不做主文案 —— 没人想用"L01"控制家里的灯。

### 2.4 离线与异常态

| 状态 | 表现 |
|---|---|
| 设备离线 | 卡片置灰，状态文字变"离线"，控制按钮禁用（**不要假装能点**） |
| 指令发送中 | 卡片半透明 + 小转圈，1 秒超时 → 恢复原状 + 底部提示"设备未响应" |
| 云端不可达 | 顶部横幅"离线模式"，所有远程操作禁用，本地局域网操作照常 |
| 手动覆盖 | 显示 `墙面开关 · 19:42`，主状态跟随实际值 |

### 2.5 夜间

必须有深色模式。理由很实在：**半夜起来看手电，白屏会晃眼**。深色模式下只保留低亮度文字与一个主操作。

## 3. 桌面端（Web 仪表盘）

### 3.1 布局

```
┌──────────┬───────────────────────────────────────┐
│ 房间列表  │  顶部指标：在线 4/4 · 今日告警 1 · 规则 6 │
│ 全部      ├───────────────────────────────────────┤
│ 客厅      │  设备卡片网格（自适应 3–4 列）           │
│ 主卧      │  ┌────┐ ┌────┐ ┌────┐ ┌────┐          │
│ 厨房      │  └────┘ └────┘ └────┘ └────┘          │
│ 卫生间    ├───────────────────────────────────────┤
│           │  最近事件（时间 · 设备 · 动作 · 来源）     │
└──────────┴───────────────────────────────────────┘
```

### 3.2 设备详情页

| 区域 | 内容 |
|---|---|
| 头部 | 名称、房间、固件版本、在线状态、信号强度 |
| 主体 | 实时值 + 历史曲线（默认 24 小时，可切 7 天） |
| 控制 | 该能力的完整控制（滑条/按钮） |
| 操作记录 | 最近 20 条，含来源与时间 |
| 危险操作 | 重命名、移房间、重启、OTA（放在最下方，需二次确认） |

### 3.3 场景编辑（吸收 HA 的三段式）

```
场景名：烟雾报警开窗
触发    [设备] [S01 烟雾] [>=] [1]
条件    [设备] [C01 在线] [==] [1]
动作    [设备] [C01 窗帘] [设为] [100%]
冷却    60 秒
开关    ● 启用
```

**必须用表单向导，不许要求用户写 YAML。** 这是 HA 最大的门槛，我们要避开。

## 4. 终端（旧手机壁挂）

### 4.1 形态

```
闲置安卓手机 → 支架/壁挂 → 全屏浏览器（Fully Kiosk 类）
                            ↓
                      加载我们的 PWA
```

| 项 | 设置 |
|---|---|
| 显示 | 常亮、禁止休眠、隐藏浏览器 UI、屏蔽通知 |
| 尺寸 | 字号放大一档：主状态 ≥ 24px，**三米外可读** |
| 亮度 | 白天 100%，夜间降到 20% |
| 告警 | 强制亮屏 + 声音 + 全屏红色 |
| 自启 | 开机自动进入 Kiosk |
| 电池 | ⚠️ 见 4.3 |

### 4.2 首页内容（比手机更简化）

只显示：**4 个场景键 + 在线数 + 告警**。
不要设备网格 —— 站在墙前的人只想知道"家里怎么样"，不想翻列表。

### 4.3 旧手机三个坑

| 坑 | 解法 |
|---|---|
| **长期插电电池鼓包** | ① 拆电池直供（部分机型可行）；② **用一个智能插座控电**：充到 80% 断、掉到 30% 充 —— 让项目自己的第一个真实用例诞生；③ 选带充电管理的支架 |
| **安卓杀后台** | Fully Kiosk Browser + wake lock + 关闭电池优化 + 允许自启 |
| **屏幕烧屏（OLED）** | 优先用 LCD 旧机；OLED 机型要定时微移像素或降低亮度 |

> 第 ① 条的"智能插座控电"这个用法，同时也是**给系统做压力测试**：
> 如果终端能连续 30 天不掉线，说明你的系统真的稳。

## 5. 51 按键条（配套物理端）

旧手机有"看"，没有"按"。51 面板补上这一半。

| 键 | 功能 | 要求 |
|---|---|---|
| K1 | 全屋关灯 | 刻字或贴标 |
| K2 | 回家模式 | 同上 |
| K3 | 离家模式 | 同上 |
| K4 | 报警静音 | 同上，且**任何状态下按下都生效** |

LCD1602 只显示一行摘要，例如：

```
全部在线 4/4  烟雾!
```

**这一条吸收的是 KNX 面板的哲学**：墙上那个东西不需要好看，需要"不用看也能按对"。

## 6. 视觉语言（统一约定）

| 语义 | 表现 | 禁止 |
|---|---|---|
| 正常在线 | 实心小圆点（绿） | — |
| 离线 | 置灰 + "离线"文字 | 只用颜色区分（色盲不友好） |
| 指令发送中 | 半透明 + 转圈 | 直接变成目标状态 |
| 手动覆盖 | 显示来源与时间 | 只显示状态不说来源 |
| 告警 | 红色横幅 + 必须点确认 | 自动消失（会被忽略） |
| 危险操作 | 二次确认弹窗 | 单击即执行 |

**字号底线**：手机主状态 ≥15px，终端 ≥24px；关键数字（温度、电量）单独放大。
**颜色规则**：开关状态**不靠红绿**，靠文字与图标 —— 因为红绿对比在色盲用户眼里几乎一样。

## 7. 明确不做的功能（克制清单）

| 不做 | 理由 |
|---|---|
| 电商/推荐入口 | 米家的反面教材，用户反感 |
| 社交分享 | 与产品无关 |
| 多套主题皮肤 | 维护成本高、收益低 |
| 三级以上菜单 | 违背"≤2 次点击" |
| AI 语音助手（v1） | 复杂度高，先做好按钮 |
| 用户头像/成就体系 | 智能家居不是社交产品 |
