## 1. 一句话

**低成本自研中介物 + 中高成本专用介质 + 第三方生态协议桥接**；家里放一台自刷固件的闲置旧手机统管，云端管异地与 AI；不造家电，最大限度利用好现在的智能家居，实现跨生态全屋智能。

## 2. 全景：六层与三阶梯接入（v2.1）

```
┌─ 云端 ───────────────────────────────────────────────┐
│  MQTT Broker · 规则引擎 · Web 仪表盘 · 异地通道 · AI   │  ← 我们做
└──────────────────────────────────────────────────────┘
┌─ 界面 & 终端 ────────────────────────────────────────┐
│  手机 PWA · Web 仪表盘 · 壁挂终端（自刷固件旧手机 Kiosk）│  ← 我们做
└──────────────────────────────────────────────────────┘
┌─ 节点与接入层（中介物）──────────────────────────────┐
│  ① 低成本自研：C3 + 继电器/插座 · 红外管 · 按键并联 · 三档  │  ← 我们做
│  ② 专用中高成本：RS485/Modbus 模块 · 机械指 / 舵机    │  ← 我们做
│  ③ 软件协议桥接：米家/华为/涂鸦 局域网协议 Bridge      │  ← 我们做
└──────────────────────────────────────────────────────┘
┌─ 实体电器层（虚线）──────────────────────────────────┐
│  用户既有老家电（灯/热水器/空调） + 成套智能家电（洗衣机/锁）│  ← 用户已有
└──────────────────────────────────────────────────────┘
┌─ 物理兜底（虚线）────────────────────────────────────┐
│  墙面开关 · 三档选择器 · 应急拨杆                      │  ← 不经过芯片
└──────────────────────────────────────────────────────┘
```

**读法**：
- **核心原则**：不造智能电器整机，只造“让万物连入中枢的那一层”。
- **三阶梯接入策略**：
  1. **低成本自研中介物（~15元）**：C3 节点负责灯、插座、老空调红外、电热水器，带三档物理兜底；
  2. **中高成本专用介质（~50元）**：RS485/Modbus 模块或机械指，负责新风、地暖、电动窗帘；
  3. **生态协议桥接网关（0元硬件）**：本地中枢运行协议 Bridge，直接聚合小米洗衣机、华为门锁等成套智能设备，打破品牌壁垒。

### 2.1 节点形态与桥接方式

| 形态 | 适用范围 | 依赖介质/协议 |
|---|---|---|
| GPIO 型 | 1–4 台设备（灯、插座、风扇、热水器） | 继电器 / 电流检测 / 三档选择器 |
| 红外型 | 一个房间的红外设备（空调、电视） | 红外发射管 + 状态矩阵码库 |
| 总线型 | 一条总线上的 N 台设备（新风、地暖） | RS485 模块 + Modbus 点表 |
| **生态桥接型** | 成套智能家电（洗衣机、微波炉、智能锁） | 局域网 Bridge（miIO / HiLink / Tuya） |

> 总线型是最省的：一条 485 总线可挂 32 台标准负载，靠地址区分。
> 如果新风、地暖、空调内机都在同一条总线上，**一块 C3 就够**。

## 3. 十台家电（最终清单）

### 第一梯队 · MVP（3 台，做完就算项目成立）

| 编号 | 名称 | 房间 | 类型 | 功能 |
|---|---|---|---|---|
| **L01** | 客厅主灯 | 客厅 | 开关 | 开/关；墙面开关、手机、场景都能控 |
| **C01** | 客厅窗帘 | 客厅 | 行程 | 0–100% 定位；开/关/停 |
| **S01** | 温湿度 | 主卧 | 传感 | 温度/湿度上报；触发规则（如热了开风扇） |

### 第二梯队 · 体验完整（+6 台）

| 编号 | 名称 | 房间 | 类型 | 功能 |
|---|---|---|---|---|
| L02 | 餐厅吊灯 | 餐厅 | 开关 | 开/关 |
| L03 | 主卧灯 | 主卧 | 开关 | 开/关 |
| F01 | 风扇 | 客厅 | 开关 | 开/关（经 12V 插座） |
| H01 | 热水器 | 厨房 | 开关 | 开/关；**长尾动作，加热约 20 分钟，可预约** |
| S02 | 烟雾 | 厨房 | 传感 | 烟雾告警；触发"开窗通风" |
| S03 | 人体 | 客厅 | 传感 | 有人/无人；回家离家判定 |

### 第三梯队 · 进阶（+1 台）

| 编号 | 名称 | 房间 | 类型 | 功能 |
|---|---|---|---|---|
| D01 | 门锁 | 玄关 | 开关+鉴权 | 开/关；本地鉴权优先；开锁留痕；fail-safe（断电即开） |

> 编号规则：`L` 灯 / `C` 窗帘 / `F` 风扇 / `H` 加热类 / `S` 传感器 / `D` 门锁 + 两位序号。
> **编号只在调试页面出现，界面上永远显示名称。**

## 4. 终端有什么功能

硬件 = **闲置旧手机（自刷固件 / 专用系统 + Kiosk 壁挂）** + 可选外挂物理按键（盲操按键条）

> **架构注记**：51 单片机算力不足以支撑中枢，中枢核心（Broker + 规则引擎 + 协议 Bridge）全集成在旧手机系统内。

| 功能 | 说明 |
|---|---|
| 全屋状态总览 | 每台设备一行：名称 · 状态 · 谁在何时操作的（含自有中介物与第三方桥接设备） |
| **本地中枢集成** | 单体自跑本地 MQTT Broker、规则引擎与米家/华为局域网 Bridge |
| **4 个物理场景键** | 全关 / 回家 / 离家 / 报警静音（独立按键外设，盲操与应急） |
| 告警弹窗 | 红色全屏 + 声音 + **必须手动确认**才消失 |
| 断网可用 | 局域网自闭环，显示最后已知状态并标注"离线"，物理键仍生效 |
| 时间与网络 | 顶部一行 |
| 不做的 | 不做设备列表翻页、不做繁杂配置 —— 那去手机上做 |

## 5. 云端有什么功能

硬件 = 先跑在自己电脑上（本质就是一台服务器，搬家时只换地址）

| 模块 | 功能 |
|---|---|
| **Broker** | 消息中枢；retain 保存最新状态；LWT 标记在线/离线 |
| **规则引擎** | 三段式：触发 / 条件 / 动作；场景与自动化共用一套 |
| **Web 仪表盘** | 设备卡片、按房间分组、历史曲线、告警中心、操作日志、设备管理（含 OTA） |
| **异地通道** | 内网穿透或云服务器，让 4G 手机能进来 |
| **AI（M9，暂不做）** | 人脸/行为识别；结论作为一条消息接入，不碰其他三层 |

## 6. 手机有什么功能

形态 = PWA 网页（加到主屏幕，像 App），不做原生 App

| 功能 | 说明 |
|---|---|
| 设备卡片 | 2 列网格；**同类多台可切换编号**（`‹ 1/3 ›`）；开关类点击即切 |
| 场景键 | 回家 / 离家 / 睡眠 / 全关 |
| 告警 | 顶部红条 + 推送；需确认 |
| 异地控制 | 4G 直连云端 |
| 离线态 | 明确显示"离线"，按钮置灰，**不假装能点** |

## 7. 六条联系

| # | 谁到谁 | 走什么 | 作用 |
|---|---|---|---|
| 1 | 电器 → 终端 | 局域网 | 低延迟控制与状态上报（主路径） |
| 2 | 电器 → 云 | 公网 | **终端挂了仍能远程** |
| 3 | 手机 → 终端 | 局域网 | 在家首选，快且不耗流量 |
| 4 | 手机 → 云 | 公网 | 异地控制 |
| 5 | 终端 → 云 | 公网 | 状态同步、规则备份 |
| 6 | 人 → 物理开关 / 应急拨杆 | 纯电路 | **永远可用，不经过任何芯片** |

## 9. 建设顺序（八步）

| 步 | 做什么 | 完成标志 |
|---|---|---|
| 1 | 单节点（窗帘） | 手机蓝牙直连能让窗帘动，不需要 broker |
| 2 | 接本地总线 | 手机同网 MQTT 能控灯 |
| 3 | 加第二节点 | 两台同时在线，拔掉一台另一台照常 |
| 4 | 打通异地 | 手机关 WiFi 用 4G 能控 |
| 5 | 中枢编排 | 回家/离家场景跑通，带进度有取消 |
| 6 | 三端界面 | 手机 + 电脑 + 终端，看到的是同一份状态 |
| 7 | 工程化 | 断网可用、断电恢复、OTA 升级 |
| 8 | 门锁 + AI | 进阶，不急 |
